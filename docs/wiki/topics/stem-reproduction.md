# ステム再現による音作りの分析手法

公開されたステムとMIDIがある曲を、パートごとに自分で作り直して原曲と計測で比べる手法である。
作り直した音と原曲の差を数値で詰めていくと、その差を埋めるのに要った操作（EQ量、包絡、ステレオ幅、バスとマスターの処理）が原曲の音作りの計測値になる。
1曲目の結果は[ただ選択があった](../works/フロクロ_ただ選択があった/index.md)にある。
動かし方は`stem-repro`スキル（`docs/skills/stem-repro/SKILL.md`）にある。

## 指標

| 指標           | 定義                                                                                                           |
| -------------- | -------------------------------------------------------------------------------------------------------------- |
| スペクトル差   | 40 Hzからナイキスト周波数までの1/3オクターブ28帯の長時間平均スペクトルを、最大値で揃えて比べた平均絶対差（dB） |
| 包絡差         | 10 msごとのRMSを最大値で揃え、-50 dBで下を切ってから比べた平均絶対差（dB）                                     |
| 音程差         | クロマの平均ベクトルのコサイン距離を10倍した値                                                                 |
| 音色探しの採点 | スペクトル差に包絡差の半分を足した値。詰める段階では音程差と、ノート頭から揃えた包絡の差も足す                 |
| ステレオ幅     | サイドとミッドのRMSの比（dB）。-100 dBを下回るものはモノラルである                                             |
| レベルの伝達   | 10 msのRMSを入力の大きさで3 dB刻みに分け、出力との差の中央値を出したもの。圧縮の効き方がわかる                 |

## ステム同士の分析

曲全体の数値だけでは、どのパートがどこを受け持っているかが分からない。
`interstem`は次の5つを出す。

| 項目                    | 中身                                                                                         |
| ----------------------- | -------------------------------------------------------------------------------------------- |
| band_owner              | 1/3オクターブ帯ごとに、その帯のエネルギーを多く持つ上位3パートと割合                         |
| beat_phase_db           | 1拍を48分割し、位相ごとの平均パワーを4つおきに出したもの。ダッキングや音を短く切る形が見える |
| low_kick_vs_bass        | 150 Hz以下の包絡についての、キックとベースの相関と、キックが持つエネルギーの割合             |
| stereo                  | パートごとのステレオ幅と左右の偏り                                                           |
| section_balance_rel_mix | セクションごとの、ステムの和に対する各ステムのラウドネス                                     |

## 音色の差の分け方

包絡差が残ったら、音色を合わせ込む前に、何が違うのかを数値で確かめる。
`timbre`は、原曲と作り直した音を同じ区間で比べ、次の3つを出す。

| 項目              | 中身                                                                                                                                      |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| swap              | SMSで倍音と残差に分け、倍音だけ、または残差だけを原曲のものに入れ替えたときのスペクトル差と包絡差                                         |
| descriptors       | スペクトル重心、ロールオフ、平坦度、フラックスを、ノートの頭から0〜30、30〜80、80〜150、150〜300 msの区間ごとに平均したもの（原曲、自作） |
| harmonics_diff_db | 1〜12倍音の強さを同じ4区間で平均し、自作から原曲を引いたもの                                                                              |

倍音の検出にはMTGのsms-toolsを使い、基本周波数はMIDIから与える。和音でも、鳴っている音ごとに倍音を取る。
入れ替えて包絡差が大きく減る側を主因とする。倍音側なら`design`でフィルターと包絡から音色を組み、残差側ならノイズの層を足す。
どちらの入れ替えでも減らないときは、ノートの位置や長さを疑い、小節ごとの包絡差を見る。

分析の手順は、音色の定量分析の文献に従った。
記述子は、Timbre Toolbox（Peeters他、JASA 2011）が挙げるもののうちlibrosaで計算できるものを使う。
使う関数は`spectral_centroid`、`spectral_rolloff`、`spectral_flatness`と、スペクトルフラックスを出す`onset.onset_strength`である。
フラックスは、対数スペクトルの差分を二乗して平均し平方根を取る旧式から、dB差分の正の部分を平均する式に変わった。式と尺度が違うので、旧式で取った値とは比べられない。
平均値ではなくノートの頭からの時系列で比べるのは、明るさがノートの中で動く形の違いを見るためである。
倍音と残差の分解は、SMS（Serra）を実装したMTGの[sms-tools](https://github.com/MTG/sms-tools)を使う。倍音の差かノイズの差かを、片方だけ入れ替えて確かめられる。
CLAPなどの埋め込みの距離は、ジャンルや音源の種類も混ざるため候補の絞り込みにしか使えないとされている。まだ入れていない。

## 気をつけること

画面なしのSurgeはパッチを読んだ直後の音が変わらない。0.3秒の無音を一度鳴らすと反映される。
音色探しは一部の音色で固まったり落ちたりする。pebbleのプロセスプールで1音色に30秒の制限を付け、超えたものや落ちたものは飛ばす。
採点にピッチを入れないと、ドラム系の音色が旋律パートの上位に混ざる。詰める段階では音程差を足した。
キックを複数発の平均波形に合わせると、位相のずれた尾は打ち消し合って短くなる。パワーで平均してから合わせる。
セクションごとのラウドネスは無音部分を除いて測るため、まばらなステムでは実際より大きく出る。拍の位相ごとのパワーと合わせて読む。
ノイズで作り直した音は低域が漏れる。後でマッチEQを当てて戻す。
ノイズの作り直しは短い窓ほど包絡が合う。「ただ選択があった」ではトップとfillが128点、stringsが64点、シンバルが512点で一番近かった。
マッチEQは最小位相のFIRで2回かける。4095タップの直線位相FIRはアタックの前に音が漏れ、キックやarpの頭が鈍る。1回ではキックのように18 dB近く削る帯域が残る。
小節より細かい音量は、ノートの頭から揃えて合わせる。キックとarp1はこれで包絡差が半分以下になった。
MIDIには鳴っていないノートが混ざる。ノート頭の音量が原曲の上位0.5%から30 dB以上低いノートは除く。
パッチの読み込みはpedalboardの`load_preset`が.vstpresetしか読めず、Surgeの.fxpは読めない。そのためVST3の状態にfxpの中身を差し込んでいる。
マスターの比較では、レベルの伝達が平らかどうかを先に見る。ゲインとピークの処理を分けずにリミッターだけで音圧を上げると、小さい音まで持ち上がって伝達が傾く。
バスの処理を和のピーク基準のリミッターで真似ると、一番大きいところだけを5 dB以上潰す。最大値で揃える包絡差は、そのぶん全体で大きく出る。バスはコンプレッサーで当てはめる。
既存のリファレンスマスタリングのMatchering 2.0は、上限を0 dBFSに抑えるため-9.1 LUFS、クレスト9.7 dBまでしか上がらない。原曲は-7.5 LUFS、クレスト8.1 dB、True Peak +1.4 dBである。
pedalboardのClipping（硬いクリップ）は、クレストを8.0 dBに揃えるとTrue Peakが+2.2 dBになり、ソフトクリッパーより原曲から離れる。
書き出しは同じ設定でも毎回少し変わる。音色探しの採点は0.3程度ぶれる前提で比べる。
包絡差は小節ごとにも出す。1曲目のベースは、差の大半がブレイクの8小節に集まっていた。MIDIのノート位置の誤りで、音色の調整では直らない。
採譜の誤りは、その区間だけ別の採譜に差し替えるか、ステムの音量から16分ごとに鳴っている所を起こし直す。
原曲が-80 dB以下で無音の区間は、作り直した音も無音にする。音量の書き込みなどで切っている区間は、ノートの長さでは再現できない。
arpのように短く刻むパートは、採譜の長さがばらつく。Surgeの包絡はノートの長さで変わるので、16分のグリッドに揃えて長さを固定する。
sms-toolsはnumpy 2未満を要求すると宣言しているが、numpy 2で動く。uvの`override-dependencies`でnumpy 2に揃えている。
残差の強さだけを写してノイズで作り直すと、synthは包絡差が悪化した（4.1から4.9 dB）。残差にも位相の構造があり、ノイズでは置き換えられない。

## 自作の部品と参考にした文献

キック、ノート単位の音量、バスとマスターの当てはめは自作である。既存のライブラリで比べた結果はPR #118のコミットにある。
記事と論文も探し、次の方針に従った。

| 部品           | 探したもの                                                                                                             | 従った方針                                                                                                                                          |
| -------------- | ---------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| キックの打点   | ドラムの打点をテンプレートで検出する論文（Yoshii、Goto、Okuno）                                                        | 1つの種テンプレートを曲の実際の音に合わせ直してから照合すると精度が上がる。複数発を揃えた中央値をテンプレートにし、波形の相関で位置と強さを出す     |
| ノートの音量   | 楽譜を手がかりにノートごとの強さを推定する研究（Ewert、Müller 2011、Jeong他 2020）と pyAMPACT                          | 揃えたノートの頭の周りの強さをノートごとに測る。原曲のMIDIで時刻がずれないステム単体なので、DTWやNMFは使わず、ノート間のRMSで測る                   |
| ソフトクリップ | クリッパーの折り返しとオーバーサンプリングの解説（Slate Digital、Sir Audio Tools、ARCLIP）                             | 折り返しを抑えるにはオーバーサンプリングする。当てはめでは、オーバーサンプリングする場合としない場合の両方を候補にする                              |
| 音色の組み立て | VSTの音色合わせの論文（Yee-King他 2018、InverSynth II、Hayes他 2025のSurge XTでのフローマッチング、Instrumental 2026） | 学習型はSurge XTを大量に鳴らして学習する手間が要り、公開コードも確かめられなかった。Instrumentalに従い、初期音色から始めてCMA-ES（pycma）で合わせる |
| 採譜の整形     | MIDIのクオンタイズ（midii、miditoolkit、pretty_midi）                                                                  | midiiはmidoのファイルを刻みごとに丸めるが、長さを16分に固定し同じ位置の重複を最大ベロシティに寄せる処理は無い。秒単位のノートの列に直接かける       |
| 無音区間       | librosaの`effects.split`                                                                                               | 既定はピーク基準なので、`ref=1.0`で絶対値の-80 dBにして使う。自作の判定と99.5%一致した                                                              |

「ただ選択があった」では、両方を候補にしてもオーバーサンプリングしない側が選ばれた（クレスト8.1 dB、True Peak +1.8 dB）。原曲のTrue Peak +1.4 dBは、オーバーサンプリングしないクリップに近い。自分の曲を仕上げるときは、オーバーサンプリングしたクリッパーを使う。
