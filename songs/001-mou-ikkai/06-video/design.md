# 001「もういっかい」映像設計書 v1

作成: 2026-10-06 / 工程: 映像設計 → 次は全編の書き出しと自己解析
実装: apps/video（Remotion）/ 判断の記録: [log.md](../log.md)

## 1. 方針

企画書7章のとおり、文字だけで組む高密度型にする。
手本はSymphony in Acidで、同じ文字列を色と配置だけ変えて何度も出し、切り替えはハードカットに限る。
ズーム、回転、ディゾルブ、イージングの動きは使わない。
映像の差分は「反復の中の1〜2要素」に絞り、AI映像にありがちな変化過多を避ける（plans/repetition-aesthetics.md）。

## 2. 時間の格子

フレームレートは48fpsにした。160BPMの8分音符がちょうど9フレームになり、カットを8分の格子へ誤差なく置ける。
16分音符は4.5フレームなので、4フレームと5フレームを交互に使う（最大0.5フレームの丸め）。
参照MVは24〜30fpsで撮られている。1フレームだけの中間状態は、本作では2フレーム（約42ms）とし、参照の1フレームに長さを合わせた。

歌詞のタイミングは推定しない。楽譜から作った vocal.tsv の全モーラを tools/lyric-timing で16分音符単位のJSONにし、Remotionがフレームへ換算する。
カットはすべて16分の格子の上に置く（±0フレーム）。

## 3. 語彙

色は5色に限る。背景と文字の組を5つの状態として持ち、状態ごとに「まだ歌っていない字」の薄い色と、今の字の強調色を決める。

| 状態   | 背景         | 文字 | 強調 | 使う所                       |
| ------ | ------------ | ---- | ---- | ---------------------------- |
| ink    | 黒 `#0b0b0b` | 白   | 赤   | 基本                         |
| paper  | 白 `#f4f4f0` | 黒   | 赤   | B、サビ                      |
| rec    | 赤 `#ff3b2f` | 黒   | 白   | サビ、刻み（録音ランプの赤） |
| signal | 黄 `#ffe14d` | 黒   | 赤   | Chorus2以降だけ              |
| ash    | 灰 `#6e6e6e` | 白   | 黒   | 語りのループだけ             |

書体はNoto Sans JPだけを使い、歌詞は900、カウンタと再生時刻は400にする。
配置は中央、左上、右下、右端の縦書き、敷き詰め（3×4）の5つだけを使う。
文字の大きさは、刻みの1字（640px）、フック（250px）、歌詞の行（84〜170px）、敷き詰め（84px）の4段にする。

モチーフは5つに絞った。

| ID  | モチーフ     | 中身                                                      |
| --- | ------------ | --------------------------------------------------------- |
| M1  | フック札     | かなの「もういっかい」6字。歌ったモーラだけ字が立つ       |
| M2  | 歌詞の行     | 表記どおりの1行。今の語を強調色、歌う前の語を薄い色にする |
| M3  | 刻みの1字    | 今鳴っているモーラ1字を全画面で出す                       |
| M4  | 再生バー     | `▶ 0:01.5 / 0:03.0` と16区画のバー。3秒は2小節にあたる    |
| M5  | 回数カウンタ | フックが鳴っている間だけ左下に `#07` のように出す         |

M5のカウンタは曲全体のフックの通し番号（1〜35）で、歌詞の「何回目かは もう知らない」を数字で見せる。
B1とBreakの末尾にある無音は、何も置かない黒の画面にする。

## 4. カット密度の目標

参照MVの全面切替は、静的型が毎分0〜17回、高密度型が毎分33〜157回である（docs/wiki/topics/mv-analysis-v2.md）。
最も密なSymphony in Acidは平均で毎分157回、最密区間で毎分279回だった。
本作は曲全体の平均を高密度型の帯の上側（毎分120〜160回）に置き、セクションで密度を大きく上下させる。

| セクション    | カットの規則                              | 設計値（回/分） | 参照の目安                    |
| ------------- | ----------------------------------------- | --------------- | ----------------------------- |
| Intro / Outro | 行頭（2小節ごと、3秒のループ1回分）       | 20 / 15         | Symphonyのイントロは切替なし  |
| A1 / A2       | 行頭だけ。行の中は語の強調の部分切替      | 20              | スライ村の平均33より少ない    |
| B1 / B2       | 1小節→2拍→1拍と加速。最後の1拍は無音      | 110             | 私だけの魔法。の平均82        |
| Chorus1 / 2   | 毎拍。小節頭だけ2フレームの中間状態を挟む | 160             | Symphonyの平均157             |
| Drop1         | 8分ごと。拍頭で2フレームの中間状態        | 320             | Symphonyの最密279より少し上   |
| Bridge        | 行頭だけ。配置は中央、色はinkのみ         | 20              | 静的型の帯                    |
| Break         | 8分→16分へ加速。最後の1小節は無音         | 405             | 本作の最大。3小節だけ         |
| LastChorus    | 16小節は毎拍、延長8小節は8分              | 213             | —                             |
| 曲全体        | —                                         | 131             | 高密度型の帯（33〜157）の上側 |

設計値は apps/video の絵コンテから数えた。
DropとBreakはSymphonyの最密区間を上回るが、変わるのは1字の位置と背景色だけで、文字の内容は同じ「も」が続く。

1フレームだけ別の状態を挟んで元に戻るフラッシュ（A→B→A）は使わない。参照8曲ではほぼ使われていないためである。
代わりに、サビの小節頭と刻みの拍頭では、次の状態の白黒を反転した絵を2フレーム挟んでから確定させる（A→B→C）。

## 5. 反復のルール

同じセクションの種類には同じ規則を使う。カット表は規則から決まるので、Chorus1とChorus2は同じカット割りになる。
サビ3回の差分は1要素ずつにする。Chorus2は色の巡回の4番目をpaperからsignal（黄）に替え、LastChorusは延長8小節のフックを敷き詰めにする。
B1とB2の同一行（2行目と4行目）は、同じ位置で同じカットになる。

フック「もういっかい」35回は、すべて中央の同じフック札で出す。
札の字は動かさず、変えるのは背景の色状態だけにする。歌ったモーラから字が立ち、「っ」も1字として扱う。
DropとBreakでは、フックに入るまで今のモーラ1字（多くは「も」）を全画面で出し、配置を4つの位置で巡回する。
Breakだけは、カットの3割で字を `■` に置き換える。どのカットを置き換えるかはシード付き乱数で決め、毎回同じ結果になる。

IntroとOutroは、再生バーの付いたループで始めて終える。語りの行（Intro 1〜3行目、Outro 2〜3行目）は灰色にし、歌になった行から黒に変える。
Outroの最後の「またね」は、灰色のまま1回だけ出す。

## 6. 音源の差し替え

Remotionは音源をpublicディレクトリから読む。既定は songs/001-mou-ikkai/04-reaper/render/mou-ikkai-mix.wav で、REAPERの書き出し先と同じ場所である。
本ミックスが同じ名前で書き出されれば、そのまま差し替わる。名前が違う場合は、レンダーの `--props` で `audio` を指定する。
尺とタイミングは楽譜から作るため、ミックスを替えても映像の側は作り直さなくてよい。

## 7. 未確定と次工程

全編の書き出しは、Intro〜Chorus1（0:00〜1:12）で描画と同期を確かめてから行う。
全編を書き出したら、参照MVと同じ手法（analysis/v2/scripts/mvan.py）で本作を解析し、設計値と実測を比べる。
フォントはGoogle Fontsから読むため、ネットワークのない環境では書き出せない。
